# Изолированный Smart SYN-тест для MTProxy

## Цель

Проверить найденный в telemt community серверный обход `Telegram handshake timeout` для одного проблемного пользователя МегаФона, не затрагивая основной MTProxy и проблему VPN.

## Область изменения

- Только альтернативный адрес `87.247.157.120:443` на RuVDS.
- Основной MTProxy, Hetzner, конфигурация пользователей и бот не изменяются.
- Текущие параметры `client_mss` пока сохраняются, чтобы менять только один фактор.

## Решение

На входе альтернативного адреса создать отдельную таблицу nftables с правилом для новых TCP SYN:

- пропускать не более `54/minute` с `burst 1` для одного source IP;
- лишние SYN немедленно отклонять через ICMP `host-unreachable`, чтобы Android быстро повторял соединение;
- применять правило в `input` после существующего redirect, но проверять через conntrack исходное назначение `87.247.157.120:443` и выделенный порт telemt `29444`;
- сохранять счётчики правила для проверки попадания трафика.

Правило устанавливается отдельным oneshot systemd-сервисом. До изменения сохраняются конфигурация telemt и полный ruleset nftables. Откат удаляет только созданную таблицу и сервис.

## Проверка

1. Убедиться, что отдельный `telemt-sch42-direct` продолжает слушать `29444` и сервис активен.
2. Проверить синтаксис и наличие новой nftables-таблицы.
3. Проверить доступность `87.247.157.120:443` извне.
4. После попытки пользователя посмотреть счётчики accept/reject и лог telemt.

Успех: проблемный Android подключается к альтернативному MTProxy; основной прокси продолжает работать. Неуспех: соединение по-прежнему заканчивается `Telegram handshake timeout`, после чего правило удаляется или исследуется следующая гипотеза.
